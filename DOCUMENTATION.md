# Документация «Инспектор ИИ»

## Назначение

«Инспектор ИИ» — локальный сервис для сопоставления проектной (ПД), рабочей (РД) и исполнительной документации (ИД). Система регистрирует документы и редакции, извлекает текст и значения, формирует карточки возможных расхождений, показывает исходные страницы и сохраняет решение инспектора в версионированном протоколе.

Проектная документация используется как база сравнения. Машинный результат служит подсказкой: подтверждение нарушения, отклонение результата или запрос уточнения выполняет инспектор.

Поддерживаемые форматы: PDF, DOCX и XML. Каталог версии 1.1 содержит 132 параметра. Способ обработки зависит от параметра: текстовые и числовые значения извлекаются автоматически, сложные графические случаи допускают ручное выделение доказательной области.

## Сценарий работы

1. Инспектор создаёт объект и загружает документы.
2. Сервис определяет формат, стадию, реквизиты и редакцию документа.
3. Worker извлекает текстовый слой или запускает OCR для скана.
4. Инспектор выбирает актуальные редакции ПД, РД и ИД.
5. Сервис извлекает значения и сопоставляет их с выбранной ПД.
6. Возможное расхождение отображается с файлом, страницей, цитатой и областью доказательства.
7. Инспектор подтверждает, отклоняет или отправляет результат на уточнение.
8. Система сохраняет версию JSON/PDF-протокола и журнал действий.

## Архитектура

```text
Браузер
   │
   ▼
FastAPI / OpenAPI ───────────── локальное файловое хранилище
   │                                      │
   ├──────── PostgreSQL ──────────────────┤
   │          │                           │
   │          └─ устойчивая очередь       │
   ▼                                      ▼
Worker ── PDF/DOCX/XML ── OCR ── локальные модели
   │
   ▼
Доказательства → решение инспектора → JSON/PDF-протокол
```

| Компонент | Назначение |
|---|---|
| Web UI | Объекты, документы, результаты, доказательства и протоколы |
| FastAPI | REST API, роли, OpenAPI и выдача интерфейса |
| Worker | Последовательная обработка и продолжение заданий |
| PostgreSQL | Реестр, страницы, факты, очередь, решения и аудит |
| Локальное хранилище | Исходные файлы, кеш страниц, экспорты и журналы |
| Tesseract | OCR русскоязычных и англоязычных сканов |
| Qwen3.5-4B | Извлечение структурированных значений из текста |
| Qwen3-VL-8B-Instruct | Чтение выбранных областей чертежей и таблиц |

PostgreSQL используется и как база приложения, и как устойчивая очередь. Поэтому для MVP не требуются RabbitMQ и Redis. Задания имеют идентификатор процесса, статус, контрольную точку и возможность продолжения после ошибки.

## Стек

- Python 3.14, FastAPI, Uvicorn и psycopg;
- PostgreSQL 16;
- PyMuPDF, python-docx и openpyxl;
- Tesseract OCR с языками `rus` и `eng`;
- локальный OpenAI-совместимый сервер моделей;
- HTML, CSS и JavaScript;
- Docker и Docker Compose;
- JSON/PDF-экспорт протоколов.

Документы и запросы моделей остаются в локальном контуре. Внешние LLM, OCR и VLM API для обработки документов не используются.

## Хранение и трассируемость

При регистрации файла вычисляется SHA-256. Доказательство содержит идентификатор и хеш файла, стадию, редакцию, страницу, нормализованные координаты, цитату и извлечённое значение.

Решения инспектора хранятся отдельно от машинного результата. Исправление доказательства создаёт новую запись. Протокол содержит версии матрицы, парсера и моделей, хеш состава документов, выбранные редакции и решения инспектора.

| Путь | Содержимое |
|---|---|
| `data/` | загрузки, кеш, экспорты и журналы; не входит в Git |
| `_extracted/` | предварительно распакованный корпус; не входит в Git |
| `docs/` | матрица параметров 1.1 |
| `examples/` | пример JSON-протокола |

## Требования

- Docker Desktop либо Docker Engine с Compose;
- не менее 8 ГБ свободной оперативной памяти;
- локальный сервер моделей с OpenAI-совместимым API;
- модели `qwen3.5-4b` и `qwen3-vl-8b-instruct`;
- свободный порт 8000 либо порт из `WEB_PORT`.

Контейнеры обращаются к серверу моделей по адресу `http://host.docker.internal:1234/v1`, если в `.env` не задан другой `DOCKER_LM_BASE_URL`.

## Развёртывание через Docker Compose

```powershell
git clone https://github.com/AGBullet/hackaton10.git
cd hackaton10
Copy-Item .env.example .env
notepad .env
```

В `.env` обязательно замените `PGPASSWORD`, `APP_AUTH_SECRET`, `APP_ADMIN_PASSWORD` и `APP_ML_PASSWORD`.

```powershell
docker compose up --build -d
docker compose ps
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

После запуска доступны:

- интерфейс: `http://127.0.0.1:8000`;
- Swagger UI: `http://127.0.0.1:8000/docs`;
- OpenAPI JSON: `http://127.0.0.1:8000/openapi.json`.

Журналы и остановка:

```powershell
docker compose logs --tail=100 web worker
docker compose down
```

Команда `docker compose down` не удаляет `data/` и том PostgreSQL.

## Запуск без Docker на Windows

После установки PostgreSQL, Tesseract и Python:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\scripts\start.ps1
```

Остановка: `.\scripts\stop.ps1`.

## Временный стенд через Tuna

В `.env` задайте:

```dotenv
ALLOW_REMOTE=1
WEB_PORT=8001
```

```powershell
docker compose up --build -d
Invoke-RestMethod http://127.0.0.1:8001/api/health
winget install --id yuccastream.tuna --exact
tuna config save-token "НОВЫЙ_ЛИЧНЫЙ_ТОКЕН"
tuna http 8001
```

Публичный URL выводится в терминале Tuna. Терминал должен оставаться открытым. `.env` и токен не входят в Git. Если используется ранее запущенная локальная установка с данными на порту 8000, запускайте `tuna http 8000`: Docker и локальная установка могут использовать разные базы.

## API

Полный актуальный контракт доступен в `/docs` и `/openapi.json`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Состояние API, БД, worker и ресурсов |
| GET/POST | `/api/session` | Текущая роль и локальный вход |
| GET/POST | `/api/objects` | Список и создание объектов |
| GET | `/api/objects/{id}` | Карточка объекта |
| POST | `/api/objects/{id}/upload` | Загрузка документов |
| POST | `/api/objects/{id}/manifest` | Ожидаемый состав документов |
| GET | `/api/objects/{id}/documents` | Реестр документов |
| POST | `/api/objects/{id}/revisions` | Выбор актуальных редакций |
| POST | `/api/objects/{id}/prepare` | Запуск обработки и сопоставления |
| GET | `/api/jobs` | Очередь заданий |
| POST | `/api/jobs/{id}/pause` | Приостановка задания |
| POST | `/api/jobs/{id}/resume` | Продолжение задания |
| GET | `/api/parameters` | Каталог 132 параметров |
| GET | `/api/objects/{id}/checks` | Состояние проверок |
| GET | `/api/objects/{id}/findings` | Карточки результатов |
| POST | `/api/findings/{id}/review` | Решение инспектора |
| POST | `/api/findings/{id}/evidence` | Исправление доказательства |
| GET | `/api/objects/{id}/search` | Поиск по извлечённому тексту |
| GET | `/api/documents/{id}/pages/{page}/image` | Изображение страницы |
| POST | `/api/documents/{id}/vision` | Чтение выбранной области VLM |
| GET/POST | `/api/objects/{id}/protocol` | Предпросмотр или создание протокола |
| GET | `/api/objects/{id}/export/{format}` | Экспорт JSON или PDF |
| GET | `/api/objects/{id}/audit` | Журнал действий |

Примеры:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
Invoke-RestMethod http://127.0.0.1:8000/api/parameters

$Body = @{ name = 'Тестовый объект' } | ConvertTo-Json
Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8000/api/objects `
  -ContentType 'application/json' -Body $Body
```

Пример результата: [`examples/protocol.json`](examples/protocol.json).

## Роли и безопасность

Предусмотрены роли инспектора, администратора и ML-инженера. Административная и ML-роли защищаются локальными паролями из `.env`. Секреты, документы, журналы, веса моделей и пользовательские данные не помещаются в Git.

По умолчанию сервис слушает только `127.0.0.1`. `ALLOW_REMOTE=1` предназначен для временного стенда. Для промышленного размещения необходимы внешний шлюз, TLS, полноценная идентификация пользователей, резервное копирование и мониторинг.
