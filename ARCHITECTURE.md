# Архитектура и стек

Сервис состоит из FastAPI, PostgreSQL, отдельного процесса обработки и веб-интерфейса на HTML/CSS/JavaScript. PostgreSQL одновременно хранит данные приложения и устойчивую очередь задач: у каждой задачи есть `process_id`, статус, контрольная точка и история повторов. Кеш и исходные файлы лежат на локальном диске. Такая схема выполняет разрешённый заказчиком контракт асинхронной pull-обработки без Redis и RabbitMQ.

Путь данных: загрузка или серверный импорт → реестр с SHA-256, стадией и редакцией → извлечение PDF/DOCX/XML и OCR Tesseract → поиск фрагментов в PostgreSQL → извлечение значений локальной моделью и проверка цитат → сопоставление с выбранной ПД → карточка доказательств → решение инспектора → версия JSON/PDF протокола. FastAPI публикует OpenAPI на `/docs` и `/openapi.json`.

Локальные модели доступны через OpenAI-совместимый API. Основной текстовый помощник — `qwen3.5-4b`; визуальный помощник — `qwen3-vl-8b-instruct`. Модель не подтверждает нарушение. Цитата, страница, файл и нормализованные координаты проверяются до показа кандидата. Для плохого OCR и спорных редакций используются статусы качества и уточнения.

Редакции выбираются по объекту, стадии, шифру, статусу утверждения и основанию инспектора. При отсутствии достоверной цепочки редакций сервис не объявляет противоречие подтверждённым. Полнота определяется ожидаемым манифестом; если он не задан, полнота не подтверждается. После дозагрузки связанные параметры пересчитываются, старые версии протокола остаются в истории.

Исходный документ и машинные результаты не перезаписываются решением инспектора. Исправления доказательств и отзывы хранятся отдельно с автором и временем. Экспорт протокола содержит версии матрицы/модели, хеш состава документов, исходные страницы и решения. Интерфейс поддерживает просмотр ПД/РД/ИД рядом и ручное выделение области в координатах видимой страницы.

Контракт хакатонного MVP реализован частично: 132 параметра есть в каталоге, но графическая топология, отсутствие элементов на чертеже и полная предметная автоматизация не реализованы. Публичные ответы TRAIN не входят в индекс поиска или модельный вывод; если они импортированы как демонстрационные карточки, их происхождение указано в интерфейсе.
