# Развёртывание и офлайн-пакет

## Контейнерный запуск

1. Установите Docker Engine/Compose и локальный сервер моделей. Убедитесь, что модели `qwen3.5-4b` и `qwen3-vl-8b-instruct` уже загружены в нём. Закрытый контур не должен зависеть от загрузки весов из Интернета во время проверки.
2. Скопируйте `.env.example` в `.env`, замените четыре значения `CHANGE_*` и при необходимости задайте `DOCKER_LM_BASE_URL`. Не коммитьте `.env`.
3. Выполните `docker compose up --build -d`. Первый запуск создаст схему БД и импортирует матрицу 1.1. Веб-интерфейс: `http://127.0.0.1:8000`; OpenAPI: `http://127.0.0.1:8000/openapi.json`.
4. Выполните `docker compose ps` и `docker compose logs --tail=80 web worker`. Проверка API: `curl http://127.0.0.1:8000/api/health`.

Содержимое `data/` и том `pgdata` сохраняются при остановке. Папка `_extracted/` доступна контейнерам только для чтения. Для передачи корпуса поместите распакованные разрешённые документы в `_extracted/` и обновите реестр из интерфейса; архивы и пользовательские документы не входят в публичный репозиторий. Для установки без сети заранее передайте сохранённые Docker-образы, зависимости и локальные веса моделей. Команда `docker compose up --no-build -d` использует уже загруженные образы.

Образы можно передать отдельно от Git:

```powershell
docker compose build
docker pull postgres:16
docker save -o inspector-docker-images.tar inspector-ai:local postgres:16
Get-FileHash inspector-docker-images.tar -Algorithm SHA256
# На машине проверяющих после сверки SHA-256:
docker load -i inspector-docker-images.tar
docker compose up --no-build -d
```

Сервер моделей и файлы весов передаются отдельным пакетом. Проверьте локальный ответ `/v1/models` и совпадение идентификаторов моделей из `.env` до запуска обработки. Сам Docker-образ приложения весов не содержит.

## Что передать проверяющим

- Публичный репозиторий с кодом, Dockerfile, Compose, фиксированными версиями зависимостей, README и этой инструкцией.
- Отдельный офлайн-пакет с разрешённым корпусом и локальными весами моделей, их версиями, лицензиями и SHA-256. Веса и документы не помещаются в Git.
- Ссылку на доступный стенд, OpenAPI (`/openapi.json`) и пример протокола (`examples/protocol.json`). Стенд должен использовать локальный сервер моделей; внешний LLM/OCR/VLM API не подходит для зачётного прогона.

RabbitMQ/Redis в архитектуре отсутствуют осознанно: PostgreSQL обеспечивает сохранение и повтор задач. Для промышленного внедрения отдельно потребуются аутентификация пользователей, эксплуатационная интеграция ИАИС «РиН», настоящая УКЭП, резервирование и нагрузочные испытания.

## Временный стенд через Tuna

Для показа из Windows задайте в локальном `.env` значения `WEB_PORT=8001` и `ALLOW_REMOTE=1`, запустите Compose и проверьте `http://127.0.0.1:8001/api/health`. Затем установите Tuna, сохраните личный токен вне репозитория и выполните `tuna http 8001`. Туннель следует держать включённым только на время проверки; `.env` и токен не должны попадать в Git.
